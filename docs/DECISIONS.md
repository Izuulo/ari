# Decisions

Where the PRD and the Claude Code docs disagree, the docs win. Checked against Claude Code v2.1.318 docs (hooks, statusline, plugins, tools-reference) on 2026-11-05.

## Doc discrepancies

| # | PRD says | Docs say | What ARI does |
|---|---|---|---|
| D1 | Open question: do subagent tool events carry `agent_id`? | Yes. Tool events inside a subagent carry `agent_id` and `agent_type`. | Attribute directly from the hook payload. No transcript tailing for attribution. Transcripts are read only for token totals (M3). |
| D2 | `PostToolUseFailure` "verify it exists" | Exists. `error` string; Bash/PowerShell failures start with `Exit code N`. `is_interrupt` optional. `PostToolUse` fires only on success. | Failures come only from `PostToolUseFailure` and `StopFailure`. No exit-code sniffing in `PostToolUse`. |
| D3 | Tasks from TaskCreate/TaskUpdate/TodoWrite in `PostToolUse` | The task tools are **off by default** on newer models (Opus 5.x etc.), opt-in via `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`. `TaskCreated` / `TaskCompleted` hook events also exist. | Capture all three tools in `PostToolUse` plus `TaskCreated`/`TaskCompleted`. Many sessions will legitimately show `no plan yet`. |
| D4 | `SubagentStart`/`SubagentStop` give transcript path | Only `SubagentStop` has `agent_transcript_path` and `last_assistant_message`. | Store transcript path from `SubagentStop`; derive it lazily otherwise. |
| D5 | Notification → `NEEDS YOU` | `notification_type` values include `permission_prompt`, `idle_prompt`, `agent_needs_input`, `elicitation_dialog`, `elicitation_url_dialog`, plus non-blocking ones (`auth_success`, `agent_completed`, …). | Only `permission_prompt`, `idle_prompt`, `agent_needs_input`, `elicitation_dialog`, `elicitation_url_dialog` set `NEEDS YOU`. |
| D6 | `rate_limits.*.resets_at` format unspecified | Unix epoch **seconds**. | Parse as epoch seconds. |
| D7 | Cache hit % computed from token fields | Statusline also sends `prompt_cache.hit_ratio` (session-level, main conversation only) since v2.1.251. | Per-turn and per-session hit % from transcripts (matches subagents too); `prompt_cache` used as fallback. |
| D8 | Hook timeout "short" | `timeout` is in **seconds**. `async: true` exists. | Synchronous hooks, `timeout: 1`. Sync keeps event order intact for loop detection; the binary runs in ~1–2 ms. |
| D9 | Statusline runs "frequently" | Event-driven, debounced 300 ms; goes quiet while main session is idle. Optional `refreshInterval` (seconds, min 1). | `ari setup` adds `refreshInterval: 2` only if the user has none, so stale agents and spinners still update. |
| D10 | `ari hook <event>` | Every payload carries `hook_event_name`. | `ari hook` reads the event name from the payload; a trailing arg is accepted and ignored. |
| D12 | `Stop` = turn end | Observed (v2.1.318): `Stop` fires while a background subagent is still running; `background_tasks` lists it as `running`. Main-agent events carry no `agent_id`. | Hook records `bg` (running background tasks) on `Stop`; the reducer treats `bg > 0` as still working. |
| D13 | `meta.json` holds last activity | — | Last activity is the `events.jsonl` mtime, so hooks never rewrite `meta.json`. |
| D14 | Sum `usage` on every assistant message | Observed: one API response is split into several transcript entries (one per content block) that share `message.id` and repeat the same `usage`. | Token totals dedupe by `message.id`. |
| D15 | First user prompt = milestone label | Observed: background-agent completions arrive as a synthetic `UserPromptSubmit` whose prompt starts with `<task-notification>`. | Prompts starting with `<task-notification>` don't count as turns and never become the milestone label. |
| D22 | Spawn names and messages (hub) | Observed (v2.1.318, `fixtures/team`, `claude -p`): `Agent` input carries `name` only when the model sets it, plus `subagent_type`, `prompt`, `description`. `SubagentStart` has `agent_id` and `agent_type`, no name, and fires right after its `PreToolUse` of `Agent`. `SendMessage` input has `to` (a name) and `message` (string here); its hooks carry the sender's `agent_id`. A message to a stopped subagent wakes it: a second `SubagentStart` with the same id. `TaskUpdate` sent only `taskId` and `status`; `owner` / `addBlockedBy` are from the docs, not yet observed. No `PermissionRequest` under `dontAsk`. | A new agent id claims the oldest pending spawn of its type. Names come from `name`, else the agent type. Repeat starts don't re-claim. |
| D11 | Repo `finneritter/ari` | — | GitHub user is now `Izuulo`: repo is `Izuulo/ari`, plugin install is `/plugin marketplace add Izuulo/ari`. |

## Project decisions

- **State dir on macOS:** macOS has no XDG state equivalent and `~/Library/Application Support` has a space that is awkward in shell commands. ARI uses `$XDG_STATE_HOME/ari` if set, else `~/.local/state/ari`, on both macOS and Linux. Config likewise uses `$XDG_CONFIG_HOME` or `~/.config/ari/config.toml`.
- **Crate name:** `ari-cli` (available on crates.io; `ari` is taken). Binary is `ari`.
- **No arg-parsing crate:** eight subcommands and a handful of flags are parsed by hand to keep startup and binary size minimal.
- **Error resolution moves to M1:** the verdict needs "open errors" to tell `RETRYING` from `ON TRACK`, so signatures and resolution ship with the reducer in M1. M3 keeps stuck detection, burn rate, cache stats and tokens.
- **D16, which errors drive the verdict:** the PRD's "open errors → RETRYING" and "turn ended with unresolved errors → BLOCKED", taken literally, would mark a whole turn RETRYING, then BLOCKED, after one harmless failure (a `grep` with no match). ARI lets only unresolved failures among the last 10 tool results drive RETRYING, and BLOCKED requires the turn to end right after an unresolved main-agent failure. Older unresolved errors still count in `✗ N` and the panel.
- **D17, stuck rules:** PRD rule 3 (edit → run → fail ×3 on the same pair) is implied by rule 2: the same command failing 3× without a success in between is caught whatever happened between the failures. Rule 1 (same call 3× in the last 10) ignores repeats separated by a file edit, which is normal edit-test iteration, and ignores task-plan bookkeeping tools. Windows are per agent so parallel subagents don't add up.
- **D18, cache savings without a price list:** hardcoded per-model prices go stale. Unless `[prices]` is set, ARI derives the effective input price from the statusline's `total_cost_usd` and Anthropic's fixed ratios (output 5×, cache write 1.25×, cache read 0.1× input), then savings ≈ 0.9 × price × cache-read tokens. Labeled `≈`; hidden when cost is unknown.
- **D19, no binaries bundled in the plugin (PRD open question 1):** a plugin's `bin/` only reaches the Bash tool's PATH, per-platform binaries would bloat every clone, and claude.ai/Cowork refuse plugins with a top-level `bin/`. Install stays three steps: binary (`dist` shell installer to `~/.local/bin`, where Claude Code's own installer puts `claude`), plugin, `ari setup`.
- **Open question 3, row position:** default `top`, so ARI's verdict sits closest to the conversation; `position = "bottom"` flips it.
- **Open question 4, `ari watch --split`:** not built. `tmux split-window ari watch` already does it, and terminal multiplexers differ too much for one helper to be worth it.
- **Events are normalized in the hook:** each hook writes a compact ARI event (not the raw payload) so lines stay under 4 KB and secrets in tool inputs (file contents) never land on disk.
- **D20, compaction forecast threshold:** `thresholds.compact_pct` defaults to 90. Checked 2026-11-05 against local recordings: none contained a `PreCompact` event yet, so the default is unverified. It's configurable, and the forecast only shows within 10 turns, where a few points of error matter little. Revisit once recordings include auto-compactions.
- **D23, hub (spec `docs/superpowers/specs/2026-11-05-hub-design.md`):** messages between the lead and an agent ride that agent's spawn line instead of a separate route; the spawn line generalises to any number of agents. Agents show tokens, not dollars: the statusline's cost is session-wide. An agent's context percent uses the main window size (`context_window_size`, else 200k). Edit line counts are lines in and out of the edit's strings, not a diff. Rows show relative ages (`12s`, `3m`), so snapshots don't depend on the time zone. Out of scope: agent-team teammates in split panes (separate sessions, listed by `ari watch --all`), and the mailbox and task files under `~/.claude/teams` and `~/.claude/tasks`.
- **D21, plainer panel (UI audit, 2026-11-05):** the PRD's status face (`face`) now defaults to off: it repeated the verdict on the line below. The turn count, the cache bar, the unattributed `other` time and the `cost of mistakes` footer are gone: each repeated or contradicted something nearby (turns reset on `/clear` while tokens don't). Fixed errors no longer take two rows each; they fold into a count. A stale agent's glyph moved from `◌` (shared with idle) to `?`.
- **D24, other agents (spec `docs/superpowers/specs/2026-11-06-m7-agents-design.md`):**
  - **`--agent` flag:** Codex and dsh call `ari hook --agent codex` / `--agent dsh`; plain `ari hook` means Claude Code, so old installs and logs stay valid. dsh sends Claude Code-shaped payloads, so a flag is more reliable than guessing from fields. The app is stored in the session's `meta.json`.
  - **Tool canonicalization:** Codex and dsh tool names are mapped to their Claude Code equivalents when an event is normalized, so errors, tests, edits and subagents use one set of rules. A Codex string `tool_response` is treated as output, and a failed test run makes the call a failure. Codex gives hooks no exit code, so other failing commands aren't errors.
  - **Codex numbers from the rollout log:** context fill, tokens and 5h/7d limits come from Codex's rollout log, read like Claude Code's transcript. When the log's tail has no `token_count`, the last known totals are kept. No cost: Codex reports none.
  - **dsh has no numbers:** its payloads carry `transcript_path: ''` and it doesn't expose its session log to hooks, so no tokens or context.
  - **No dollars or blended limits across apps:** a Codex limit isn't a Claude limit, and Claude's cost is not comparable to Codex's. Multi-session screens show limits per app and total dollars for Claude Code sessions only.
  - **dsh wiring:** setup mounts the bridge in `$DSH_HOME/cordis.patch.yml` with `configPath` at ARI's hooks file. If the user's bridge already has its own file, ARI's entries go in that one and uninstall removes only those; ARI never turns off a user's own hooks.
  - **Unverified:** dsh is tested from sample data shaped after its documented payloads, not a real recorded session. The real Codex check was not run (it needs a signed-in Codex and an interactive `/hooks` approval).
- **D25, edit churn (plan `docs/superpowers/plans/2026-11-07-edit-churn.md`):** two more ways to reach STUCK, after the existing two and only while the turn is active. Churn: one agent edits one file 12 times (`CHURN_EDITS`) in the current turn with no green test run since; per agent, so parallel subagents don't add up; Markdown is skipped, so ticking a plan never counts; a green run (partial runs included) resets the count. 12 comes from 52 recorded sessions, where the worst ordinary turn edited one file 9 times. Undo: an edit whose (old, new) strings are an earlier edit's (new, old), twice (`UNDO_REPEATS`), since one revert is normal. Events carry hashes of the strings, never the text, and only for `Edit`; sessions recorded before this change only get the churn rule. Tokens while stuck are the session total in the statusline's samples now minus at the moment it got stuck, so Codex and dsh (no samples) show STUCK without them.
- **D26, redo after compaction (plan `docs/superpowers/plans/2026-11-07-compaction-redo.md`):** main only, since subagents keep their own context. Work is main's successful `Edit`, `Write`, `MultiEdit`, `NotebookEdit`, `Bash` and `PowerShell` calls, matched by input hash, the last 200 (`WORK`). Each repeated call counts once, so a build re-run in a fix loop is one redo. Test runs (with counts in their output, or a test runner word such as `go test`) and commands that only look around (`REORIENT`: `ls`, `cat`, `grep`, `git status`, `git log`, …) are skipped; a call that failed before the compaction isn't work, so retrying it is a retry, not a redo. The window opens at `PreCompact` or `PostCompact` and closes once a whole turn has started after it; a second compaction restarts the count. `REDO_MIN = 3`. It's a warning beside the verdict, never a verdict: repeating work isn't the same as making no progress, and STUCK already covers going in circles. D20 update: two local recordings now hold a real auto-compaction (2026-11-07 and 2026-11-08); replayed through these rules, both give 0 redos, so no false alarm, but no true redo has been seen yet either. `REDO_MIN` and `REORIENT` stay guesses until one is.
- **D27, test tampering (plan `docs/superpowers/plans/2026-11-07-test-tampering.md`):** three kinds of flag, all from successful calls: `skip added` (an edit adds more of `event::SKIP_MARKERS` than it removes; a marker counts only when the char before it isn't a letter, digit, `_` or `.`, so `iter().skip(1)` never does), `deleted` (a shell `rm`, `git rm`, `unlink` or `Remove-Item` of a test path, at most 5 per command), and `edited while failing` (a test file edited while the latest run is red). Editing tests while green is normal TDD and isn't flagged. Test paths: a `tests`, `test`, `__tests__`, `spec` or `specs` folder, or a name like `test_*.py`, `*_test.py`, `*_test.go`, `*_spec.rb`, `*Test.java`, `*Tests.cs`, `*.test.*`, `*.spec.*`. Shortcut: a `Write` can't see the old file, so markers already in it count as added. Not seen: deletes through `git mv`, `find -delete` or a Codex `apply_patch` (canonicalised to an `Edit`). "Unverified" needs at least one test run and ignores Markdown edits. Events carry counts and paths, never text. None of it changes the verdict: it's a note on DONE or IDLE (`tests failing` beats `unverified`) and a warning beside it.
- **D28, risky commands (plan `docs/superpowers/plans/2026-11-07-risky-commands.md`):** flagged only from `PostToolUse` / `PostToolUseFailure` of `Bash`, so only commands that ran; a command denied at the prompt fires no Post event. Rules, first hit wins: `delete outside repo`, `recursive delete`, `discards uncommitted work`, `rewrites remote history`, `deletes a branch`, `drops data`, `writes a raw disk`. Paths resolve as text against the payload's `cwd` (following `cd` inside the chain), so symlinks and variables aren't followed. The repo is `CLAUDE_PROJECT_DIR` when the hook has it, else the `cwd`: Claude Code's `cwd` follows the shell into subfolders (81 of 222 local sessions), and a delete elsewhere in the repo isn't outside it. With no `cwd` the outside rule is skipped. `gh` is a text tool like `git`, so PR bodies never read as SQL; redirects (`> /dev/null`) are never delete targets. `/tmp` and macOS temp folders are exempt from the outside rule only. The full command never lands on disk, only the matched simple command, cut to 80 chars. Not seen: scripts and task runners, unresolved variables and substitutions, aliases, other languages, file and MCP tools, PowerShell. Known false alarms: SQL keywords in a heredoc that writes a `.sql` file; `rm -r` on a harmless build folder.
