# Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A live settings screen in `ari watch` (`s`), colour themes with per-colour overrides, on/off switches for panel sections and statusline segments, live reload of `config.toml`, and config errors that are reported instead of swallowed.

**Architecture:** `Config` gains `theme` and `colors`; `hide` now also covers panel sections. A new `theme` module turns a config into a `Palette` and recolours finished output: ratatui `Line`s for watch, ANSI strings for ARI's own statusline row, so no drawing code changes. A new `settings` module holds the editable rows (value, step, reset) and draws the screen. `watch` keeps the file's config apart from command-line flags, applies an edit the key handler queued on `View`, saves, and reloads on mtime change.

**Tech Stack:** Rust 2024, ratatui 0.30 (`Color: FromStr`), serde, toml 1.2, insta. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-06-settings-design.md`

## Global Constraints

- No new crates.
- Default theme with no `[colors]` = byte-identical output. Existing snapshots change only where `s settings` is added to key hints.
- The chained statusline's output is never recoloured; only ARI's own row.
- `NO_COLOR` still wins: with colour off, nothing is painted.
- The screen never saves when the file failed to parse. A `--ascii` command-line flag is never saved.
- Theme values, role names, feature ids, steps, ranges, keys and copy are in the spec; copy verbatim: `settings need 40×10`, `fix config.toml first (or delete it)`, `couldn't save: <error>`, `chain and prices: edit the file`, the two-line file header.
- CI: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`. Snapshot updates: `INSTA_UPDATE=always cargo test`, then review every `.snap` diff.
- One commit per task (more if a task has distinct steps), `feat:`/`fix:`/`test:`/`docs:`, ending with the attribution line. Work on branch `settings`.

## Review Focus

1. **Hand-written bad values** (`theme = "neon"`, `good = "#zz"`, `colors.shiny = "red"`, `hide = ["nope"]`): render with fallbacks, no panic, `ari doctor` names each one. Tests in Tasks 1 and 2.
2. **A config.toml that doesn't parse while the screen is open**: edits refused, file untouched byte for byte. Test in Task 6.
3. **`ari watch --ascii` then changing a setting**: saved file keeps `ascii = false`. Test in Task 6.
4. **A colour override equal to another base colour** (`good = "red"`): good things turn red, bad things stay the bad colour; nothing is mapped twice. Test in Task 2.
5. **Short terminal** (fewer rows than settings): selected row stays visible while moving to the last row. Test in Task 5.

### Task 2: Themes recolour the panel, hub and statusline row

**Files:**
- Create: `src/theme.rs` (add `pub mod theme;` in `src/lib.rs`)
- Modify: `src/statusline.rs` (`own_row`), `src/watch.rs` (where frames are finished, next to the `ascii::map_lines` calls and the `--once` print)

**Interfaces:**
- Consumes: `Config.theme`, `Config.colors`, `config::ROLES` (Task 1).
- Produces:
  - `#[derive(Clone, Copy, Debug, PartialEq)] pub struct Palette { pub good, warn, bad, accent, highlight, info, muted, bar: Color }`
  - `pub fn Palette::new(cfg: &Config) -> Palette`: theme preset (spec table; unknown → default), then each parsable `colors` entry overrides its role.
  - `pub fn Palette::role(&self, name: &str) -> Option<Color>` (used by the settings swatches).
  - `pub fn lines(lines: Vec<Line<'static>>, p: &Palette) -> Vec<Line<'static>>`: maps every span's `fg` and `bg` through the base→role table (Green→good, Yellow→warn, Red→bad, Cyan→accent, Magenta→highlight, Blue→info, DarkGray→muted, Indexed(236)→bar); other colours untouched; each colour mapped once.
  - `pub fn ansi(s: &str, p: &Palette) -> String`: rewrites the params inside each `ESC[…m` (31→bad, 32→good, 33→warn, 34→info, 35→highlight, 36→accent, 90→muted) to the role's SGR fg params; other params (1, 2, 0) kept.
  - `fn sgr_fg(c: Color) -> String`: named → 30–37/90–97, `Indexed(n)` → `38;5;n`, `Rgb` → `38;2;r;g;b`, `Reset` → `39`.

- [ ] **Step 1: Write the failing tests** in `theme.rs`:
  - `default_palette_is_identity`: `lines(x, &Palette::new(&Config::default())) == x` for a line with Green/Red/Indexed(236) spans; `ansi("\x1b[1;33mhi\x1b[0m", &default) ` unchanged.
  - `theme_preset_and_override`: `theme = "soft"`, `colors.good = "red"` → `good == Color::Red`, `bad == Color::Indexed(167)`; `theme = "neon"` → equals default palette; `colors.good = "#zz"` → good stays the theme's.
  - `override_equal_to_other_base_maps_once`: with `colors.good = "red"` (default theme), a Green span becomes Red and a Red span stays Red.
  - `ansi_rewrites_color_params_only`: soft theme, `ansi("\x1b[1;32mok\x1b[0m \x1b[2m│\x1b[0m")` == `"\x1b[1;38;5;114mok\x1b[0m \x1b[2m│\x1b[0m"`.
  - `mono_resets_colors`: mono theme turns `"\x1b[31mx"` into `"\x1b[39mx"`.

- [ ] **Step 3: Implement** `src/theme.rs`.
- [ ] **Step 4: Wire it in.** `statusline::own_row`: apply `theme::ansi` to `bar::render`'s result when `color` is on (never to chained output). `watch`: apply `theme::lines` to every frame's lines in the `run_tui` closure and the `--once` print, using `Palette::new(&app.cfg)`.

### Task 4: Settings rows: values, steps, defaults

**Files:**
- Create: `src/settings.rs` (add `pub mod settings;` in `src/lib.rs`)

**Interfaces:**
- Consumes: `Config`, `THEMES`, `ROLES`, `FEATURES` (Task 1).
- Produces:
  - `pub struct Item { pub group: &'static str, pub key: &'static str, pub label: &'static str }`
  - `pub fn items() -> Vec<Item>`: spec order — LOOK (`theme`, `face`, `ascii`, `position`, `max_width`), COLOURS (`color.<role>` ×8, label = role), FEATURES (`hide.<id>` ×14, label `<id> · <what>`, `hide.tasks` labelled `task checklist`), ALERTS (`bell`, `ctx_warn`, `ctx_crit`, `stuck_repeats`, `compact_pct`), DATA (`retention_days`). 33 items.
  - `pub fn value(cfg: &Config, key: &str) -> String`: display text — `on`/`off`, `top`/`bottom`, `auto` for width 0, `60%`, `3 repeats`, `7 days`, theme name, colour value or `theme`.
  - `pub fn step(cfg: &mut Config, key: &str, dir: i8)`: dir `1`/`-1` per the spec's steps and ranges; for `hide.<id>` and booleans either direction flips; `hide` keeps its order and has no duplicates.

- [ ] **Step 1: Write the failing tests** in `settings.rs`:

  - `thresholds_stay_ordered`: `ctx_warn` stepping up stops at `ctx_crit − 5`; `ctx_crit` stepping down stops at `ctx_warn + 5`; `stuck_repeats` stays in 2..=10; `compact_pct` 50..=100; `retention_days` 1..=90; `max_width` 0→40→60, and 200 is the top.
