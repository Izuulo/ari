# `ari find` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ari find <text>` searches every Claude Code transcript under `~/.claude/projects` and prints the matching sessions newest first, each with its folder, date, first prompt, a match snippet and the exact command to resume it: `cd <folder> && claude --resume <id>`.

**Architecture:** A new module `src/find.rs`. It lists `<projects>/*/*.jsonl` (main transcripts only, not `<id>/subagents/`), sorts them by mtime, newest first, and streams each file line by line through one reused buffer. A line is parsed as JSON only when it is needed: its raw bytes contain the query (ASCII case-folded), or it can supply the first prompt, the title or the cwd. A raw hit counts only if the query is in the text you or Claude wrote (prompts, replies, session titles), not in tool output or JSON keys. A file stops being read at its first real match once the first prompt is known; the whole search stops at `--limit` sessions. That keeps a rare query on many GB to one sequential pass, and a common query to a few files.

**Tech Stack:** Rust 2024 std (`BufReader::read_until`, `fs::read_dir`), serde_json. No new dependencies.

**Spec:** `docs/ROADMAP.md` §7 item 10 (row 10: "`ari find <text>`: search every transcript, print the folder and the `claude --resume` command").

## Global Constraints

- Read-only and local: `ari find` only reads transcript files. No network, no model, nothing written anywhere (no index, no cache).
- No new crates. No regex. Never `read_to_string` or `fs::read` on a transcript: stream with `BufReader::with_capacity(1 << 16, file)` and `read_until(b'\n', &mut buf)`, reusing the buffer.
- Claude Code only. Codex and dsh are out: ARI doesn't know Codex's rollout tree (`$CODEX_HOME/sessions/…`) or its prompt records (it only reads a rollout's tail for token counts, `src/codex.rs`), and dsh exposes no session log (DECISIONS D24). Listed as an open decision.
- Projects dir: `setup::settings_path()`'s parent joined with `projects` (so `CLAUDE_CONFIG_DIR` is respected).
- Flags: `ari find <text…> [--here] [--limit <n>]`. Words after `find` that aren't flags are joined with single spaces into the query. `--limit` takes an integer `1..=500`, default `FIND_LIMIT = 10`. `--here`: only sessions whose recorded `cwd` equals the current directory (`std::env::current_dir()`), which is also the only folder `claude --resume <id>` finds them from.
- Case-insensitive for ASCII only (`make_ascii_lowercase`); `é` vs `É` don't fold.
- Output is plain text (no colour), exact copy:
  ```
  {YYYY-MM-DD HH:MM}  {tilde(cwd)}[  · {title}]
    you    {first prompt, cut to 80}
    match  {snippet}
    cd {quoted cwd} && claude --resume {id}
  ```
  One blank line between sessions. `you    (no prompt)` when none was found. Without a cwd, the last line is just `claude --resume {id}`. The cwd is single-quoted only when it has a char outside `[A-Za-z0-9/._~+-]`, with `'` written as `'\''`.
- Messages on stderr: no query → `ari find: what to look for? (ari find <text> [--here] [--limit <n>])`, exit 2; bad flag or limit → `ari find: …`, exit 2; projects dir missing → `no Claude Code transcripts in {tilde(path)}`, exit 1; nothing found → `no session mentions "{query}"`, exit 1; exactly `limit` found → `newest {limit} shown; --limit for more`, exit 0.
- CI: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
- One commit per task, `feat(find):` / `docs:` style, ending with the attribution line. Work on branch `ari-find`.
- Patch version bump in `Cargo.toml`, `.claude-plugin/plugin.json` and `Cargo.lock` (next patch after `main`'s version), one `CHANGELOG.md` "## Unreleased" bullet.

## Review Focus

1. **A transcript being written right now** (last line cut mid-JSON, or no trailing newline): no panic; the complete lines before it are searched. Test `partial_last_line_is_skipped` in Task 2.
2. **Queries with JSON-special or upper-case characters** (`say "hi"`, `C:\temp`, `TOKEN`): found, because the needle is matched in its JSON-escaped form on raw bytes. Test `quotes_backslashes_and_case` in Task 2.
3. **The query appears only in tool output or in JSON keys** (a file Claude read, `parentUuid`): not a hit, no phantom sessions. Test `only_prompts_replies_and_titles` in Task 2.
4. **A folder with spaces or quotes** (`/Users/me/My Project`, `/tmp/it's`): the resume command is quoted and pastes as one working line. Test `resume_command_is_quoted` in Task 1.
5. **Many GB of transcripts and no match**: one streaming pass, memory flat. Measured in Task 3 Step 5 against the owner's real `~/.claude/projects` (2.4 GB, 1,237 files on 2026-11-07); target under 5 s on a release build.

### Task 2: Search the transcripts

**Files:**
- Modify: `src/find.rs`

**Interfaces:**
- Consumes: `snippet`, `PROMPT_CHARS` (Task 1); `event::truncate`.
- Produces:
  - `#[derive(Debug, PartialEq)] pub struct Hit { pub id: String, pub cwd: String, pub mtime_ms: u64, pub title: Option<String>, pub prompt: Option<String>, pub snippet: String }` (`id` = file stem).
  - `pub fn search(projects: &Path, query: &str, here: Option<&str>, limit: usize) -> Vec<Hit>`: newest first, at most `limit`.
  - `fn scan(path: &Path, needle: &str, raw_needle: &[u8], here: Option<&str>) -> Option<Hit>`: one transcript. `needle` = query ASCII-lowercased; `raw_needle` = `serde_json::to_string(&needle)` without its outer quotes, as bytes (so `"` and `\` match their escaped form).
  - `fn texts(v: &Value) -> Vec<&str>`: the searchable strings of one line:
    - `type == "user"`: `message.content` if a string, else its `{"type":"text"}` items' `text` (tool results excluded);
    - `type == "assistant"`: `message.content`'s `{"type":"text"}` items' `text`;
    - `type == "custom-title"`: `customTitle`; `type == "summary"`: `summary`;
    - anything else: none.

**Per-file algorithm** (`scan`), the part the signature doesn't decide:

```text
for each complete line (read_until '\n'; a last line without '\n' is dropped):
    lower = line, ASCII-lowercased into a second reused buffer
    want = (cwd unknown   && line contains b"\"cwd\":\"")
        || (prompt unknown && line contains b"\"type\":\"user\"")
        || (title unknown  && line contains b"\"type\":\"custom-title\"" or b"\"type\":\"summary\"")
        || lower contains raw_needle
    if !want: continue
    parse the line (skip on error)
    take cwd from it if unknown; with `here` set and cwd != here: return None
    take the title from custom-title / summary if unknown
    take the prompt if unknown: type "user", not isMeta, not isSidechain, its first text
        not starting with '<', whitespace collapsed, cut to PROMPT_CHARS
    if no snippet yet: snippet = first texts(v) entry where snippet(text, needle) is Some
    if snippet and prompt are known: stop reading
return Hit when a snippet was found
```

The byte search on lines is `str::contains` on `std::str::from_utf8(&lower)` (lowercasing keeps UTF-8 valid; skip the line if it isn't UTF-8) for the needle, and `windows().any()` for the short fixed keys.

`search` lists `projects/*/` then `*.jsonl` directly inside each (no recursion, so `<id>/subagents/*.jsonl` is skipped), drops unreadable entries, sorts by mtime descending (ties by path), and calls `scan` in that order until `limit` hits.
