# M7 Codex and DeepSeek Harness Sessions, App Themes: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ARI records, shows and themes sessions from Codex and DeepSeek Harness (`dsh`) next to Claude Code, and `ari setup` wires up each app it finds.

**Architecture:** The hook command tells ARI which app is calling (`ari hook --agent codex|dsh`), and ARI stores that in each session's `meta.json`. A pre-pass in `event::normalize` rewrites Codex and dsh tool names and inputs into the Claude Code shape, so everything downstream stays as it is. For Codex sessions, `usage::load` and `tokens::update` read Codex's rollout log because there is no statusline payload. Themes gain three app presets and `auto`.

**Tech Stack:** Rust 2024, ratatui, serde_json, toml, insta snapshots. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-06-m7-agents-design.md`

## Global Constraints

- `ari hook` always exits 0, never prints, and appends one line (no heavy work), whatever `--agent` value it gets.
- A missing `--agent`, or a `meta.json` with no `"agent"` key, means Claude Code.
- Nothing a Claude Code user sees changes unless they pick a new theme. The default theme stays `default`, Claude sessions show no app label, and the existing snapshot tests pass unchanged.
- Missing numbers are left out, never shown as `0` or an empty bar.
- App themes change only accent, highlight, info, muted and bar. Good, warn and bad stay `Green`, `Yellow` and `Red`.
- Proposed colours: `claude` accent `#D97757`, `codex` near-white accent, `deepseek` accent `#4D6BFE`.
- Dollar figures (cost, cache savings) count only Claude Code sessions.
- Setup never makes users edit Codex or dsh config by hand, and never silently turns off a user's own hooks.
- Commit each step's change on its own (owner's rule). Work happens on branch `m7-agents`.

## Review Focus

1. **A Codex rollout log is large or mid-write.** Only the tail is read. A half-written last line is skipped, with no panic and no lag in `ari watch`. *(Task 3)*
2. **A brand-new Codex session has no `token_count` record yet.** Context and tokens are left out, not shown as `0%`. *(Task 3)*
3. **`~/.codex/hooks.json` already has the user's hooks, or is broken JSON.** Setup keeps every user entry. A broken file is left alone, and setup says why. *(Task 6)*
4. **`ari setup` runs twice, or `ari uninstall` runs after the user edited the file.** No duplicate ARI entries, and uninstall removes only entries whose command contains `ari hook --agent`. *(Task 6)*
5. **`ari hook --agent something-unknown`, or a `meta.json` written by an older ARI.** The event is recorded and the session is treated as Claude Code. *(Task 1)*

Facts the mapping relies on (from source, 2026-11-06):
- **Codex** (`openai/codex` `codex-rs/core/src/tools/hook_names.rs`): the shell tool is already `"Bash"` with `tool_input.command`. Edits are `"apply_patch"`, and the patch text is in `tool_input.command`. Spawning is `"spawn_agent"`. There is no `PostToolUseFailure` event; failures come as a `PostToolUse` whose `tool_response` carries the exit status. Confirm the exact field from `codex-rs/core/src/hook_runtime.rs` and the generated schema in `codex-rs/hooks/schema/generated/`, then put a real-shaped example in the fixture.
- **dsh** (`deepseek-ai/deepseek-harness` `packages/shell/tool-bash`, `packages/fs/tool-fs`, `packages/fs/tool-str-replace-editor`): the tools are `bash` (`command`), `read`, `write`, `edit` (`file_path`, `old_string`, `new_string`), `grep`, `glob`, `apply_patch`, and `str_replace_editor` (`path`, plus `old_str`/`new_str`).

Mapping, applied by `canonical`:

| Incoming `tool_name` | Becomes | `tool_input` rewrite |
|---|---|---|
| `bash` | `Bash` | none |
| `read`, `write`, `edit`, `grep`, `glob` | `Read`, `Write`, `Edit`, `Grep`, `Glob` | none |
| `apply_patch` | `Edit` | `{"file_path": <first path from lines starting "*** Update File: ", "*** Add File: " or "*** Delete File: ">}`, taken from `command`, `input` or `patch`, whichever is a string |
| `str_replace_editor` | `Edit` | `{"file_path": path, "old_string": old_str, "new_string": new_str}` |
| `spawn_agent` | `Agent` | none |

Failure rule: a `PostToolUse` whose `tool_response` exit code is a nonzero integer becomes `PostToolUseFailure` with `error = "Exit code {n}\n{stderr, else output}"`.

### Task 3: Codex numbers from its rollout log

**Files:**
- Create: `src/codex.rs`
- Modify: `src/lib.rs`, `src/usage.rs` (`load`), `src/tokens.rs` (`update`)
- Create: `fixtures/codex/rollout.jsonl`
- Test: unit tests in `src/codex.rs`

**Interfaces:**
- Consumes: `app::of`, `App::Codex` (Task 1).
- Produces:
  - `codex::read_tail(path: &Path) -> Option<Tail>`
  - `struct Tail { model: Option<String>, total: Option<Value>, last: Option<Value>, window: Option<u64>, rate_limits: Option<Value> }`. These are the latest `turn_context` and `token_count` records found in the last 256 KiB.
  - `codex::usage(path: &Path) -> Usage`
  - `codex::ledger(path: &Path) -> Option<Ledger>`

Rollout lines look like `{"timestamp":…,"type":"event_msg","payload":{"type":"token_count","info":{"total_token_usage":{…},"last_token_usage":{…},"model_context_window":N},"rate_limits":{"primary":{"used_percent":…,"window_minutes":…,"resets_at":…},"secondary":{…}}}}`. The model is in `{"type":"turn_context","payload":{"model":…}}`. Field names come from `TokenCountEvent`, `TokenUsageInfo`, `TokenUsage` and `RateLimitWindow` in `codex-rs/protocol/src/protocol.rs`. Check the line wrapper against `codex-rs/protocol` `RolloutLine` before writing the fixture.

How the numbers map:
- `ctx_used` is `last_token_usage.total_tokens`, `ctx_size` is `model_context_window`, and `ctx_pct` is used ÷ size × 100.
- `five_h` is `primary` and `seven_d` is `secondary`: `Limit { pct: used_percent, resets_at }`.
- In the `Ledger`, `input` is `input_tokens − cached_input_tokens`, `cache_read` is `cached_input_tokens`, `output` is `output_tokens`, and `ctx` is `ctx_used`. Everything comes from `total_token_usage`. `by_model[model]` holds the same numbers.
- `cost_usd` stays `None`.

  - `partial_last_line_is_skipped`: the fixture plus a truncated last line gives the same `Usage`.
  - `fresh_session_has_no_numbers`: a rollout with only `session_meta` and `turn_context` gives `ctx_pct == None` and `ledger(...) == None`.
  - `usage_load_falls_back_to_rollout`: a session dir with `meta.json` `{"agent":"codex","transcript":<fixture>}` and no `usage.json` makes `usage::load(dir).ctx_pct` `Some`. A Claude dir without `usage.json` still gives `Usage::default()`.

- [ ] **Step 3: Implement.**

  - `usage::load` falls back to `codex::usage(transcript)` when `usage.json` is missing and `app::of(dir) == Codex`.
  - In `tokens::update`, when `app::of(dir) == Codex`, `c.main` comes from `codex::ledger` and subagent reading is skipped. A comment explains the shortcut: Codex subagents aren't counted separately until a real recording shows their logs.
